# ADR 0028 — 计时工具反馈与交互模式

**简体中文** · [English](../../en/adr/0028-timed-tool-feedback-and-interaction-modes.md)

## 状态

已接受。

## 背景

事件流 TUI 已经显示工具生命周期名称，但还不足以判断正在执行什么、为何获得允许以及耗时
多久，同时也没有常驻的工作模式标识。如果只复制其他智能体的模式名称，却不把它们映射
到 Neuro Code 自己的权限边界，会产生安全风险：名为 `Auto` 的界面选项不能悄悄绕过显式
规则或进程沙箱。

客户端可以观测供应商延迟，却无法精确测量模型私有的内部推理阶段。因此计时标签必须采用
明确的本地定义，而不能冒充供应商内部遥测。

## 决策

- `AgentRuntime` 在每个模型步骤发出一次 `MODEL_THINKING_COMPLETED`。单调时钟耗时从
  `MODEL_STEP_STARTED` 开始，到第一个可见文本、本地工具调用、托管工具活动或模型终态
  为止。TUI 将其标为“思考完成”；它代表客户端观测到首个可行动结果的时间，而不是模型
  私有推理耗时的证明。
- `TURN_COMPLETED` 与 `TURN_FAILED` 携带整个轮次的单调时钟耗时。成功轮次会在最终助手
  回答之后显示耗时摘要；本地工具和供应商托管工具的终态事件也携带耗时。
- 工具反馈采用有界的树状结构：调用摘要、权限路径或授权、结果预览，再到带耗时的完成/
  失败。调用摘要只使用路径、命令、模式、查询或任务 ID 等经过选择的有用参数。ADR 0029
  在该计时契约上增加每次调用一张原地卡片、脱敏后的真实输出和有界工作区变更差异。
- `InteractionMode` 定义四种应用自有模式，可通过 `Shift+Tab` 循环或 `/mode MODE` 直接
  选择：

  | 模式 | 权限行为 |
  | --- | --- |
  | `normal` | 只读工具自动运行；副作用操作需要询问。 |
  | `accept-edits` | 只读与工作区编辑工具自动运行；命令和其他副作用需要询问。 |
  | `plan` | 只读工具自动运行；未匹配的副作用操作直接拒绝，不弹出授权。 |
  | `auto` | 安全预览在安全分类器实现前采用 `accept-edits` 行为；若启动时显式指定 `--always-approve`，则保留它已有的绕过授权。 |

- 显式 deny/ask 规则先于模式默认值判断。所有模式都必须经过已配置的工作区适配器和进程
  沙箱。提示词中的模式指引只描述行为，不能授予权限。
- 模式切换与轮次串行，在新供应商/会话绑定上重新应用，并与语言、思考强度一起保存到
  仅用户可访问的 UI 偏好文件；损坏或未知值安全回退到 `normal`。
- 常驻运行栏在模型、上下文占用和思考强度之外，显示压缩后的主目录相对工作路径及当前
  模式。主主题使用冷色蓝、紫、青、绿承担语义角色；暖色只用于警告和错误。

## 后果

用户现在可以看到模型何时给出可行动结果、整个轮次花费的墙钟时间，以及每次工具调用的
生命周期，同时不会暴露不受限制或未经脱敏的结果。四种模式立即具有实际用途，并且会如实标注尚未
完成的自动化；`Auto` 不会被误认为已实现模型安全分类器，现有显式 `--always-approve`
仍是请求不受限默认权限的唯一入口。

这些耗时属于进程本地观测，可能包含网络调度、供应商排队、授权等待或流式传输开销。
交互式卡片展开、供应商原生推理遥测和自动安全分类器仍属于后续纵向切片。
