# ADR 0060 — 计划执行任务的不可变修订快照

**简体中文** · [English](../../en/adr/0060-plan-execution-revision-snapshots.md)

## 状态

已接受

## 背景

ADR 0058 记录用户确认的计划执行生命周期，ADR 0059 则允许用户对当前计划修订提出反馈。模型整体替换
当前计划后，仅靠持久任务记录无法识别哪一份修订被交接给执行轮次。历史事件流中虽有执行请求，但它不是
小型、只读的任务审计界面。

若把可变的当前计划复制到任务视图，历史会被追溯性地改变；若把它作为调度器、审批记录或子代理结果，也会
声称任务生命周期并不具有的权限。

## 决策

- 只有类别为 `plan_execution` 的 `SessionTask` 可以携带不可变 `SessionPlan` 快照，且同样适用有界
  领域校验。旧任务记录没有快照仍然有效，`subagent` 任务不能携带快照。
- 执行轮次开始前，`AgentRuntime` 必须要求已有保存的计划，并把恰好该修订保存到新任务。终态生命周期
  转换会保留快照；后续 `update_plan` 无法更改历史。
- SQLite schema v9 为 `session_tasks` 添加有界 `plan_snapshot_json` 字段。v8 迁移会为既有任务填入
  空值。快照不进入 FTS、JSON 导出或 Rust 会话导入，且会话任务（包括快照）不会随分叉复制。
- `/tasks` 保持只读。对于带快照的执行任务，它只显示修订指纹的前 12 个字符和已完成步骤数；不渲染
  计划文本、提示词、命令、工具输出或凭据。
- 快照不会创建审批、执行、重试、调度、工作区、沙箱或子代理权限。本切片不向 ACP 新增任务方法。

## 后果

用户即使在活动计划已演进后，也能区分旧执行任务使用的计划修订，而不会在任务列表中暴露原始记录。旧数据库
记录保持可读，只是没有修订摘要。

随后由 [ADR 0061](0061-read-only-plan-execution-inspection.md) 定义对单条已保存快照的用户主动、
限当前会话只读展示。把任务结果关联到单个步骤、审批工作流、任务图、调度和子代理编排仍是独立能力。
