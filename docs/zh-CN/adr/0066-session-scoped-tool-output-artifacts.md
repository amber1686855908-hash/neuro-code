# ADR 0066：会话作用域的工具输出 artifact 读取

[English](../../en/adr/0066-session-scoped-tool-output-artifacts.md) · **简体中文**

## 状态

已接受——Stage5BM，2026-08-06。

## 背景

Stage5BK 会在本地 Bash 预览被截断时保存有界且脱敏的 artifact。Stage5BL
增加了类型化读取端口和安全的基础设施应用接缝，但该接缝只接收不透明句柄，
无法证明句柄属于发起读取的会话。因此直接把读取器暴露给入站接口会使会话可见性
变成隐式且不安全的规则。

## 决策

在现有仅接收句柄的读取服务旁增加
`SessionToolOutputArtifactApplicationService`。它会：

1. 通过 `SessionStore` 的摘要读取确认会话存在；
2. 只从该会话已持久化的事件数据派生有界、不可变的 artifact 投影；
3. 只提取 artifact ID、安全相对句柄、字节数、截断事实和事件序号；
4. 仅当请求的不透明 ID 出现在该会话投影中时才允许读取；
5. 通过 `ToolOutputArtifactReader` 读取内容，继续保留根目录约束、再次脱敏和字节上限。

投影按 artifact ID 去重，并按事件顺序返回最近的一页有界结果。损坏或不可信的
事件元数据按不可用 artifact 处理并忽略，不把它当作文件系统路径。缺少关联时返回
通用 `SessionError`，不泄露该句柄是否存在于其他会话或磁盘上。

## 边界

本阶段不增加 SQLite 表或迁移：已持久化的
`TOOL_COMPLETED`/`TOOL_FAILED` 事件投影就是现有的关联边界。不改变 Runtime、Bash、
权限、沙箱、会话项或事件类型。本阶段也不通过 CLI、TUI 或 ACP 暴露服务；后续入站
切片必须显式注入该服务，并分别定义输出展示契约。

服务不提供跨会话列表、删除、超出小型有界页的分页、绝对路径、原始参数、原始工具输出，
也不只凭调用方提供的会话 ID 授权。

## 影响

- 后续界面可以通过类型化且具有会话作用域的应用查询读取 artifact。
- 复用现有事件回放，不需要 schema 迁移。
- 没有有效 artifact 元数据的损坏或旧事件仍可读取；其 artifact 仅在投影中不可用。
- 后续 UI/CLI/ACP 阶段仍需为缺失、过期或删除的 artifact 定义用户可见契约和生命周期策略。

## 验证

测试覆盖有界事件投影、损坏元数据、去重、会话关联校验、再次脱敏和未关联不透明句柄
拒绝。应用模块继续位于现有 `application` 层，API 不泄露基础设施路径。
