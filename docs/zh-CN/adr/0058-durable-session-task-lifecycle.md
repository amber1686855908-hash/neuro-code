# ADR 0058 — 计划执行的持久会话任务生命周期

**简体中文** · [English](../../en/adr/0058-durable-session-task-lifecycle.md)

## 状态

已接受

## 背景

ADR 0057 让用户确认的计划到执行交接可以持久化，但仅有事件无法回答这项工作是否仍在运行、已经
完成、失败或被取消。现有 `BackgroundTaskManager` 拥有存活 Shell 进程树，并且刻意会在绑定切换或
进程退出时丢弃其记录。把计划执行复用为后台任务，会混淆进程所有权和对话状态，削弱其清理不变量，
还会错误地暗示计划轮次拥有一个子进程。

未来的子代理需要可观察的生命周期；但在面向用户的契约存在之前暴露调度器或工作者协议，会让尚未实现
的能力看起来已经可用。本切片必须建立持久边界，而不能启动独立工作或扩大任何权限。

## 决策

- Domain 拥有不可变的 `SessionTask` 值。它的不透明 ID 有上限且不含控制字符；规范类别为
  `plan_execution` 和预留的 `subagent`；状态为 `running`、`completed`、`failed` 与
  `cancelled`。任务恰有一个开始时间；终态任务恰有一个晚于开始时间的结束时间。它只能从
  `running` 转换一次到终态。
- `SessionStore` 拥有任务元数据的创建、更新和有界列举。SQLite schema v7 在带外键的
  `session_tasks` 表中保存它。任务会随会话删除而级联删除，不会随着分叉复制，也不进入可见内容
  搜索、JSON 导出或导入的历史 Rust 会话。
- 有效的 `/execute-plan`/`/run-plan` 交接会创建一个 `plan_execution` 任务。`AgentRuntime`
  会在规范用户消息之前发出任务开始与执行请求事件；它会在对应轮次终态事件之前记录任务完成、失败
  或取消。普通提示以及没有已保存计划而被拒绝的交接不会创建任务。
- TUI `/tasks` 命令会在本地组合当前绑定作用域的后台快照和持久会话任务元数据。它不会展示提示词、
  命令、模型输出、原始工具输出或凭据，也不能取消任一种任务。现有 `kill_task` 仍是唯一面向模型的
  进程取消操作，并继续经过权限与审批策略。
- 这是一份轮次记录，而不是任务调度器。它不会唤醒模型、运行子代理、重试任务、分配工作，也不会将
  计划评论作为其生命周期的一部分，更不会创建新的权限/工作区/沙箱绕过。`subagent` 仅为将来的纵向
  切片预留，使其可以复用同一
  生命周期值，而无需重新设计 schema。

## 后果

用户在恢复会话后，可以查看自己明确发起过的执行交接的有界、持久记录，其中包括被取消或失败的轮次。
界面也明确区分了这种对话元数据和由应用拥有的存活 Shell 进程。

有界当前计划反馈由 [ADR 0059](0059-bounded-current-plan-comments.md) 单独定义。附着到计划执行
任务的不可变计划修订随后由 [ADR 0060](0060-plan-execution-revision-snapshots.md) 定义。子代理执行、
任务评论、任务图、分配、重试和任务取消语义仍需要各自面向用户的契约与应用服务。预留类别在相应
纵向切片完成前不得被视为已经实现。
