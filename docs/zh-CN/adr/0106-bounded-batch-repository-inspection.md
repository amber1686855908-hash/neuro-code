# ADR 0106：有界批量仓库检查

## 状态

已接受。

## 背景

兼容的 `read_file`、`list_dir` 和 `grep` 工具虽然安全，但分析大型仓库时容易让每份小证据
都消耗一次模型往返。直接并行任意工具调用会扰乱审批顺序、工具结果配对、监督预留、工作区
快照、取消和事件顺序。

## 决策

在不改变既有工具的前提下增加三个只读基础设施工具：

- `read_files` 按请求顺序读取至多 16 个明确文件，使用有界行范围，隔离单文件错误，支持
  会话范围 ACP 文本读取端口，并限制合并且脱敏后的输出；
- `list_tree` 采用确定性的深度和条目上限，跳过链接以及常见元数据、依赖、缓存和构建目录，
  所有路径继续经过既有工作区解析器；
- `grep_many` 在确定且有界的 Python 文件系统遍历中搜索至多 16 个正则表达式，支持可选
  include/exclude glob，并分别限制单查询结果、总结果、扫描文件数和输出字节。

规范 registry 会在普通只读 binding 及显式隔离只读子代理能力集中暴露三者。指令和技能
tracker 保持既有单一移动目标语义：成功批量项按确定顺序更新，下一模型请求使用最后一个成功
目标。

`AgentLoopRunner` 中的工具执行继续保持顺序。这里优化的是粗粒度工具契约，而不是运行时并发。

## 结果

大型仓库的映射、搜索和证据读取可以减少模型轮次，同时不削弱权限、沙箱、取消或消息配对边界。
ACP 文件系统端口支持明确文本读取，因此可批量读取；协议没有目录遍历或仓库搜索能力，所以不能
委托目录树和多查询搜索。
