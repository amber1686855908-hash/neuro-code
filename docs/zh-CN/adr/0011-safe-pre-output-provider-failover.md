# ADR 0011：安全的输出前供应商故障转移

**简体中文** · [English](../../en/adr/0011-safe-pre-output-provider-failover.md)

状态：已接受

## 背景

命名 profile 允许一次运行在直连供应商、本地网关或 CC Switch profile 之间进行路由。
凭据缺失、端点不可达或请求在流开始前失败，都可能导致供应商暂时不可用。尝试备用项
可以提高可用性；但如果模型已经输出内容或启动托管工具，再在其他供应商上重放同一步骤，
就可能重复可见文本、副作用或费用。导入会话还可能带有只对原 profile 亲和关系有效的
不透明原生上下文。

## 决策

- `[routing] fallbacks` 是现有且互不重复的 profile 有序列表，不能包含配置中的默认
  profile。
- 候选适配器按需创建，因此备用项缺少凭据不会阻止健康的主 profile。
- 每个候选项只缓冲第一个事件。在该事件之前出现配置或供应商错误时推进到下一候选项。
  任意类型的第一个事件都是提交点；之后发生的错误直接上抛，不再故障转移。
- 每个候选项至多尝试一次。某候选项成功后，后续模型步骤从它开始，同一次运行中不会
  返回更早的候选项。
- 每次输出前失败产生 `provider_attempt_failed`，候选项首次成功产生
  `provider_selected`。对外错误文本需规范化并限制长度；所有候选项均失败时汇总错误。
- `--no-failover` 绕过候选链，只创建本次选中的 profile。
- 新建会话或仅含普通消息的会话可以采用成功备用项的供应商、模型和亲和信息。包含保留
  不透明上下文的会话继续保留已存来源；选择事件会记录来源未被更新。
- 本阶段不重试同一候选项、不跨进程推断供应商健康状态，也不实现熔断。

## 影响

启动和流开始前的失败可以恢复，同时不把 CC Switch 变成运行时依赖。故障转移保持可
观察、可预测；任何模型活动一旦可见，运行时会优先保证副作用安全，而不是继续追求
可用性。第一个事件规则刻意比“只检查文本”更严格：推理增量、本地工具调用、托管工具
生命周期事件、用量报告或完成事件也都会提交当前候选项。

选择状态仅存在于当前进程。持久化健康评分、退避、重试预算，以及在供应商之间安全
转换不透明上下文的策略，都需要另行决策和测试。
