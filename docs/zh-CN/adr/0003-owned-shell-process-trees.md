# ADR 0003：掌控 Shell 进程树，并在命令分类时失败关闭

**简体中文** · [English](../../en/adr/0003-owned-shell-process-trees.md)

- 状态：已接受
- 日期：2026-07-17
- 源代码基线：`c68e39f60462f28d9be5e683d9cbe2c57b1a5027`

## 背景

只终止直接 Shell 进程可能遗留编译器、包管理器、测试运行器或更深层的子孙进程。只针对原始命令字符串检查权限规则，也可能让被禁止的命令隐藏在 Shell 运算符、`timeout`/`env` 等包装器或内部 `bash -c` 脚本之后。无界的 `communicate()` 调用还可能在输出截断生效前耗尽内存。

固定版本的 Rust 实现会创建受控进程组，使用有界的 TERM 到 KILL 终止序列，并针对每个拆分后的命令形式评估限制性 Bash 规则。

## 决策

`ProcessTree` 是负责 Shell 生命周期所有权的平台适配器。POSIX 子进程在新会话中启动，适配器向整个进程组发送信号。Windows 子进程在新进程组中启动；在尝试温和终止后，目前使用系统 `taskkill /T /F` 作为进程树回退方案。Bash 工具并发排空标准输出和标准错误，同时每个流最多只保留配置的字节数。

权限层使用保守的 Shell 词法分析器处理简单序列。它会检查所有 `&&`、`||`、`;` 和管道片段，检查包装前后的命令形式，并在深度限制内递归分析常见 Shell 的 `-c` 调用。敏感环境变量覆盖和无法由该词法分析器安全分类的结构会标记为不完整。如果 Bash deny/ask 规则可能适用，不完整分类在交互模式下变为 `ask`，在无头模式下直接拒绝。

## 影响

- 超时和取消不会有意留下同组的子孙进程。
- 后续或嵌套的被禁命令无法隐藏在允许的前缀之后。
- 输出保留量独立于命令实际输出规模，始终有界。
- 在加入完整解析器和 Shell 文件访问模型之前，限制性策略会保守拒绝部分合法的复杂 Bash 脚本。
- 在进程树行为可标记为完全兼容之前，仍需实现 Windows Job Object 所有权。
