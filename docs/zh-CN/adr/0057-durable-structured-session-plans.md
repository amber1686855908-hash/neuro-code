# ADR 0057 — 持久化结构化会话计划

**简体中文** · [English](../../en/adr/0057-durable-structured-session-plans.md)

## 状态

已接受

## 背景

`plan` 原本已经是一种安全的交互模式：它允许探索，同时由权限策略拒绝未匹配的副作用操作。
但这项策略本身不能让用户持久、可查看地了解模型准备执行哪些工作。供应商专有的计划协议、
可写计划文件或仅 UI 的私有缓存，都会削弱既有应用边界，或让恢复与分叉后的会话彼此不一致。

参考智能体具有更丰富的审批和任务系统，但它们的私有协议不是本项目可兼容的 API。本切片必须
提供一项小而有用的能力，同时不能声称已经实现计划审批、评论或子代理。

## 决策

- Domain 拥有不可变的 `SessionPlan` 与 `PlanStep` 值。一次整体替换包含一到十二个步骤、
  可选且有界的目的，以及仅限 `pending`、`in_progress`、`completed` 的状态。领域层拒绝控制
  字符、未知字段、格式错误的 JSON 形状和超限值。
- 供应商中立、无副作用的 `update_plan` 工具接收一次完整替换。它不写计划文件、不修改工作区、
  不执行命令，也不授予任何权限。
- `AgentRuntime` 只识别工具返回的规范元数据；它会先经由 `SessionStore` 端口保存，再报告
  成功，发出 `PLAN_UPDATED`，并把当前渲染结果加入后续模型请求。没有持久会话存储的运行时会让
  工具调用失败，而不是声称计划已经保存。
- SQLite schema v6 将有界 JSON 值与有序会话项分开保存。恢复会在下一条提示前载入它，持久
  分叉会复制它。它刻意不进入 FTS 可见内容索引、JSON 导出或导入的 Rust 会话数据。
- Textual UI 增加 `/plan DESCRIPTION`：它选择已安全的计划交互模式并提交说明；同时增加
  `/view-plan` 与 `/show-plan`，在当前界面语言下本地渲染已保存计划。UI 从不解析供应商输出
  来推断计划状态。计划存在后，`/execute-plan`（别名 `/run-plan`）是仅能由用户显式发起的
  交接：它只切换到 `accept-edits`，把一次执行轮次委派给当前对话，绝不选择 `auto`，也不绕过权限。
- 没有已保存计划时，运行时会拒绝交接。交接有效时，它会在规范用户消息之前以有界计划 payload
  追加 `PLAN_EXECUTION_REQUESTED`。事件经过普通会话事件端口持久化，执行提示仍会获得当前计划
  指引。命令/网络审批、工作区包含限制、显式规则和沙箱执行均不改变。

## 后果

用户恢复或分叉会话时不会失去当前的高层工作计划，所有供应商也使用相同的工具形状。计划更新会
通过普通运行时事件序列保持可审计，同时模型指引不会污染规范消息历史。

该功能现在提供一项小型、已审阅的计划到执行切换，但不引入自动执行。逐步骤反馈随后由
[ADR 0059](0059-bounded-current-plan-comments.md) 定义；分配的工作者、共享任务图、计划文件、ACP
计划方法或子代理编排仍需要独立、面向用户的契约和生命周期所有权，不能只扩张这个元数据字段。
