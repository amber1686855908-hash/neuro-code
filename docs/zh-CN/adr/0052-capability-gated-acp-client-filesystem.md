# ADR 0052：由能力协商控制的 ACP 客户端文件系统

**简体中文** · [English](../../en/adr/0052-capability-gated-acp-client-filesystem.md)

- 状态：已接受
- 日期：2026-07-29

## 背景

ACP 定义了由客户端持有的 `fs/read_text_file` 与 `fs/write_text_file` 请求。ACP agent 不能
假定已连接客户端拥有文件系统，也不能在客户端声明远程文件系统后悄悄回退到 agent 进程的本地
文件。Neuro Code 的普通文件工具已经具备工作区约束、显式 sandbox profile、权限决策、写入时
`AGENTS.md` 发现和精确替换语义。

协议只提供文本读取与整文件写入，没有原子 compare-and-swap、目录枚举、递归搜索或删除操作。

## 决策

- 增加 canonical `ClientFileSystem` 应用端口。它按 session 作用域和能力状态工作，且只包含
  文本读写操作。
- 只有客户端至少声明一种文件系统能力后，ACP 入站适配器才创建该端口，并在新建、加载、恢复或
  分叉 session 时绑定它。Bootstrap 经 composition root 传递该端口；应用代码绝不导入 ACP
  SDK 类型。
- 绑定该端口时，`read_file` 会委托给 `fs/read_text_file`。其路径只接受 session 根的词法
  校验；宿主机不得解析、检查或把客户端目标替换成本地路径，行范围仍保持现有上限。必须声明
  读取能力；已委托的操作不会回退到本地。
- 对于已委托客户端，只有同时声明读写能力才注册 `search_replace`。它保留 session 根、sandbox、
  额外目录、指令预检、精确匹配、歧义检查和普通权限门禁，然后经端口读写。最终写入的原子性、
  链接语义和文件系统身份由客户端负责，因为协议无法由宿主机表达。
- 每个客户端文本响应和写入请求都限制为 1 MiB。客户端异常或畸形文本会转换为稳定且失败关闭的
  `ToolError`，绝不回显客户端错误或凭据。
- 终端操作继续与本文件系统切片保持分离。ADR 0053 随后只增加由能力协商控制的前台可执行文件；
  既有本地目录/搜索/命令工具不会被 ACP 文本文件系统方法重新定义。

## 影响

- 声明文本文件系统能力的客户端可以接收工具读取和精确替换，而 Neuro Code 不会为该委托操作
  直接使用自身本地文件内容。
- 只读客户端不会获得变更工具；未声明客户端能力时，普通本地工具行为保持不变。
- 该能力刻意保持很窄。客户端终端 framing、文件系统枚举/搜索/删除、多媒体、WebSocket 和扩展
  仍是独立的协议切片。
