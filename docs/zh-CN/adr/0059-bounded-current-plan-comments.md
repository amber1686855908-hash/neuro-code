# ADR 0059 — 当前计划修订的有界评论

**简体中文** · [English](../../en/adr/0059-bounded-current-plan-comments.md)

## 状态

已接受

## 背景

ADR 0057 让结构化计划可持久化，但用户审阅计划时，无法在不发送含义模糊的普通提示的前提下，把反馈
附着到某个具体步骤。可写计划文件、供应商专有审批协议或后台任务评论流，都会模糊反馈、执行和工作者
生命周期之间的边界。

产品需要一项小型、本地且持久的反馈机制。它不能声称评论会批准计划、启动工作、调度任务或创建子代理。

## 决策

- Domain 拥有不可变的 `PlanComment` 值。评论具有不透明 ID、从 1 开始的步骤索引、有界文本和带时区的
  创建时间戳。一个计划修订最多可拥有 48 条评论。
- `SessionPlan` 从规范化、已校验的表示派生 SHA-256 指纹。`SessionStore` 只接受并列出恰好属于该当前
  计划的评论。并发计划替换后再添加反馈会失败，而不是把它附着到另一份计划。
- SQLite schema v8 在带外键的 `session_plan_comments` 表中保存评论，并按会话和计划指纹划分作用域。
  此表不进入 FTS、JSON 导出或 Rust 会话导入。替换计划会删除早期指纹的评论；清除计划会删除其全部
  评论。会话分叉只会复制当前计划评论，并为其生成新的不透明 ID。
- `AgentConversation` 会与会话计划一起恢复当前评论。下一次普通请求或计划执行请求时，`AgentRuntime`
  会把它们渲染为临时、供应商中立的计划指引。`update_plan` 整体替换会在后续模型步骤前清空内存中的
  评论。评论不是规范消息或运行时事件。
- TUI 提供 `/comment-plan STEP COMMENT` 和 `/plan-comment STEP COMMENT`；`/view-plan` 与
  `/show-plan` 会在对应编号步骤下渲染评论。该命令不会发起供应商请求，在轮次运行时不可用。本切片不向
  ACP 暴露计划评论方法。
- 此功能不会改变任何权限决策、工作区规则、沙箱策略、执行模式、任务状态或子代理生命周期。

## 后果

用户可留下简短、持久且针对步骤的反馈，并在恢复会话或分叉当前计划后查看。模型只会在用户下一次要求
它行动时看到这些反馈，从而让审阅保持独立于执行。

替换计划会刻意移除旧反馈，而不是猜测变化后步骤之间的映射。用户可在新修订上重新添加反馈。任务评论、
计划审批、调度、共享工作者分配、ACP 计划方法和子代理编排仍是独立能力。
