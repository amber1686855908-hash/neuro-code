# ADR 0001：采用 Python 模块化单体，而非镜像 crate 结构

**简体中文** · [English](../../en/adr/0001-modular-monolith.md)

- 状态：已接受
- 日期：2026-07-17
- 源代码基线：`c68e39f60462f28d9be5e683d9cbe2c57b1a5027`

## 背景

源工作区包含 70 多个 crate 和约 419,000 行 Rust 代码。它的 crate 边界受到 Rust 编译方式、所有权、生成式单仓库结构以及历史迁移的影响。照搬这些边界会产生大量 Python 包，却不能改善运行时隔离。

## 决策

使用单一发行包和单一导入包，并在其中明确划分领域、应用、端口、适配器、接口、工具和平台模块。依赖方向从接口指向领域契约；基础设施只能在组合根中选择。只有外部消费者或进程边界证明有必要时，才拆出独立版本的软件包。

## 影响

- 端到端纵向切片无需协调多个软件包的发布即可演进。
- 边界由静态类型和测试约束，而不是由 Cargo 强制。
- 上游 crate 到 Python 模块是多对多映射，应记录在兼容性证据中，而不是编码进目录名。
- 随着代码库增长，必须加入导入环和禁止依赖检查。
