# ADR 0027 — TUI 语义渲染与应用层思考强度

**简体中文** · [English](../../en/adr/0027-semantic-tui-and-application-reasoning-effort.md)

## 状态

已接受。

## 背景

稳定消息 TUI 已经消除了回答跳动和重复角色前缀，但把助手回答按普通文本显示仍会丢失
Markdown 层级。本地生命周期通知的正文起始位置也不统一，关键标识符缺少视觉层次，当前
模型只会短暂出现在启动或状态消息中。

面向用户的“思考强度”还会带来另一类准确性风险。不同供应商 API 的参数名称与语义并不
一致，许多模型根本没有这类参数；工作流编排也属于应用能力，而不是模型设置。界面不能
在只有 Neuro Code 自有审查策略时，暗示供应商私有控制或子代理工作流已经生效。

## 决策

- 助手输出使用 Rich 的 Markdown 文档模型和固定的应用自有语义主题。标题、强调、代码、
  列表、链接及表格按各自角色使用克制配色。链接点击被禁用，模型内容也绝不会作为
  Rich/Textual markup 解释；用户提示、查询、路径、标识符和外部值继续按字面文本显示。
- 本地系统、状态、工具和错误条目采用两列表格，左侧是固定宽度标签栏，右侧正文允许
  折行。插值值根据供应商/模型、工具/会话、路径、结果、强度或错误等应用已知语义着色；
  载荷文本本身不能选择样式。
- 提示框正上方常驻运行栏，显示当前供应商、模型、工作区、上下文窗口占用、请求强度与
  交互模式。本 ADR 规定强度/上下文语义，模式由 ADR 0028 规定；请求值与
  实际值不同时同时显示两者。上下文先显示带标记的本地估算，模型步骤完成后改用供应商
  报告的输入加输出 token。正整数 profile 字段 `context_window_tokens` 提供分母；窗口未知
  时保持 `?`，该元数据也绝不会作为 API 参数发送。状态栏由控制器状态驱动，可本地化，
  并在供应商选择/故障转移和强度切换时刷新；窄窗口中仍保留关键信息。TUI 等待模型输出
  时，本地化的待完成助手文案前会显示七格折叠脉冲。它由用户提供的终端演示移植为
  Textual 定时器，在完成、取消或失败时停止，并且不会直接写 ANSI 光标控制序列。
- 输入 `/` 时显示纯文字提示栏，并与行内建议共用同一确定性目录。语法包含参数、强度
  选项、可选择的 profile 名和自由文本参数占位符。`Tab` 只在主提示框的斜杠命令中应用
  第一项候选，不会替代模态框的焦点切换。
- `ReasoningEffort` 定义六项供应商中立选择：`low`（`○`）、`medium`（`◐`）、
  `high`（`●`）、`xhigh`（`⬤`）、`max`（`◆`）与 `ultracode`（`⚡`），默认值为
  `high`。`max` 是普通单智能体的最深策略；`ultracode` 是有界编排的显式应用层入口。
  这些值描述逐步加深的应用层审查策略，不代表能够保证模型的隐藏推理 token 预算。
- `Ctrl+E`、不带参数的 `/effort` 和 `/reasoning` 打开 TUI 选择器；`/effort LEVEL` 与
  `/reasoning LEVEL` 可以直接选择。交互和无头组合都支持 `--effort LEVEL`。活动轮次中
  禁止切换，新值从下一次模型步骤开始生效。
- `UiPreferencesStore` 把 TUI 请求强度与界面语言一起写入原子替换、仅用户可访问的
  `ui-preferences.json`。显式 CLI 值在本次启动中优先于保存的 TUI 值；强度缺失、损坏或
  未知时安全回退到 `high`。供应商配置和凭据不受影响。
- `ProfileConversationController` 持有进程内选择，让切换与模型轮次串行，并在新 profile/
  会话绑定安装后重新应用。强度不属于会话身份，也不会写入规范对话历史。
- 每个模型步骤都会由 `AgentRuntime` 把实际审查指引加入仅用于本次请求的系统消息，并在
  `ModelContext` 上携带有类型的请求值。注入的指引不会进入持久化 `SessionItem`。
- 供应商适配器不会把 `ModelContext.reasoning_effort` 盲目转换成私有请求字段。显式的 Kimi K3
  与 GLM 5.3/5.2 dialect 会把 `max` 映射到已配置的原生 `max` 字段；其他 dialect 会省略
  原生强度字段，但仍收到应用层指引。每项映射都必须按供应商/模型显式声明并测试。
- `ultracode` 的请求值是 `ultracode`，供应商兼容投影为 `max`。选择器和运行栏可以显示
  该投影，但显式用户回合会进入 durable application delegation service，并准确选择
  `MAIN_MAX` 或 `BOUNDED_SWARM` 中的一条路径。供应商永远不会收到编造的原生 `ultracode`
  值。详见 [ADR 0141](adr/0141-automatic-ultracode-delegation.md)。

## 后果

助手回答结构与关键本地状态更容易浏览，同时模型或外部文本无法注入界面样式。当前
供应商/模型、上下文预算占比以及准确的请求/实际策略保持可见，不再依赖转瞬即逝的对话
通知。供应商用量可以纠正低成本的启动估算，无需捆绑 tokenizer；没有配置窗口时宁可不
显示占比，也不会编造。命令语法与选项变得可发现，同时不会重新引入冲突的 Textual 命令
面板。

思考强度获得了跨供应商可用的行为，但其边界仍保持透明：它调整 Neuro Code 在请求级
加入的审查指引，不能保证供应商内部推理深度、token 分配、延迟或成本。策略指引会占用
少量请求上下文，因此每次按需重新生成，而不是写入会话。

ADR 0029 随后加入有界的原地工具卡片，ADR 0030 再加入有界的交互详情切换。Mermaid、
内嵌媒体，以及工作流/子代理编排仍属于后续纵向切片。

## 兼容性说明

这是应用自有行为，不代表已经与历史 Rust 项目或任何供应商专用 CLI 达成线路级对齐。
以后若实现供应商原生控制，必须另行记录其能力与边界。
