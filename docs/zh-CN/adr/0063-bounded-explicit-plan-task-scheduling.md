# ADR 0063：有界显式计划任务调度

- 状态：已接受
- 日期：2026-08-02

## 背景

计划执行已经是显式、受权限控制的交接。用户可能希望先准备多个经过审阅的计划修订，再启动其中一个；
但应用不能把规划悄悄变成自主调度或子代理执行。

## 决策

应用提供两个本地、显式的 TUI 命令：

- `/schedule-plan`（别名 `/queue-plan`）在不联系供应商的情况下保存当前计划的一份不可变快照。
- `/run-task TASK_ID` 在用户指定不透明 ID 后启动一个已排队计划任务。

每个会话最多包含四个处于排队状态的 `PLAN_EXECUTION` 任务。Conversation 会先检查上限以便立即反馈，
SQLite store 也会在创建任务的事务内再次检查，以保证跨实例安全。`SessionStore.start_session_task` 会原子地
把 `queued` 转为 `running` 来认领任务；只有排队任务可以被认领。既有 `/execute-plan` 和 `/run-plan` 仍然创建并立即运行
`running` 任务，因此行为保持不变。

已有的 `session_tasks.status` 文本列已经接受规范值，因此这次生命周期扩展不需要提升 schema 版本。旧数据库
仍可加载，因为新的 `queued` 值由领域模型解释，而不是依赖迁移。

排队任务不会自动启动、重试、唤醒模型、绕过普通计划交接执行工具或创建子代理。它们仍是会话所有的持久元数据和
不可变计划快照。分叉、导出和导入沿用现有 SessionTask 策略：任务记录不会复制到快照或被序列化。

## 影响

该调度器有意只是有界持久化和显式认领的接缝，不是后台调度器。运行时预算、供应商契约、权限检查、工具执行、取消和
Finalizer 行为保持不变。未来的子代理编排或自动调度需要单独的 ADR 和新的显式生命周期契约。
