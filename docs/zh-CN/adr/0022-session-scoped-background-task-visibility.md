# ADR 0022：把后台任务可见性限制在当前会话

**简体中文** · [English](../../en/adr/0022-session-scoped-background-task-visibility.md)

- 状态：已接受
- 日期：2026-07-18
- 源代码基线：`c68e39f60462f28d9be5e683d9cbe2c57b1a5027`

## 背景

ADR 0021 引入了由进程所有权约束的后台 Shell 任务，但第一版组合把一个注册表共享给所有
TUI 会话绑定。这个范围比固定 Rust 基线更宽；基线中的后台注册表属于单个会话。切换
profile 或在进程内恢复会话后，共享注册表可能暴露前一个会话的任务 ID，也可能让任务继续
运行却没有可达的所有者。

用户还需要在不反复询问模型的情况下看到这些任务。本地界面不能打印原始任务输出或可能
含敏感信息的命令文本，也不能提供绕过已有 `kill_task` 权限与审批路径的终止捷径。

## 决策

组合根持有一个 `BackgroundTaskSupervisor`。每个 TUI `ConversationBinding` 都获得新的
`BackgroundTaskManager` 作用域。作用域只能启动、检查、等待和终止自己的任务 ID；监督器
仍跨作用域掌控全部进程，因此应用关闭时可以终止每一棵仍存活的进程树。

成功切换 provider 或会话时，系统先验证替换绑定，再关闭旧作用域，最后发布新绑定。关闭
作用域会终止仍运行的进程树并丢弃记录。替换绑定被拒绝时，也会关闭新分配的作用域。选择
结果会报告被终止的活动任务数量，让 TUI 明确显示清理行为。

TUI 新增不接受参数、只读的 `/tasks` 命令。它最多列出当前作用域中的 20 条记录，只显示
完整任务 ID、生命周期状态、退出码、输出字节数/截断标记及开始时间，不渲染命令和捕获
输出。有界周期轮询会在每个任务首次进入终态时发出一次本地通知。轮询失败保持静默，避免
反复污染对话记录；用户显式执行 `/tasks` 时则会显示错误。

`/tasks` 不能终止任务。终止仍通过面向模型的 `kill_task` 工具，因此继续经过
`PermissionManager` 及交互审批。面向模型且仅含元数据的完成提醒属于
[ADR 0023](0023-model-visible-background-task-completion-reminders.md) 定义的独立边界；本切片
不会自动唤醒模型，也不会注入完成输出。

## 影响

- 任务 ID 和记录不能跨越 profile/会话绑定，但在清理完成前，应用仍掌控所有子进程。
- 切换绑定会明确终止旧作用域任务，而不是留下不可访问的命令；界面会显示终止数量。
- 即使快速任务在两次轮询之间完成，也会产生一次终态通知；重复轮询不会重复通知。
- 任务列表可用于查看状态和发现 ID，同时不会把原始工具结果或命令文本复制到滚动记录。
- 跨重启/恢复的任务持久化、模型自动唤醒、完成输出注入、富任务面板、多任务等待，以及
  具有独立审批设计的用户直接终止能力仍是后续工作。

源证据来自固定历史提交中的每会话 `BackgroundTaskRegistry`、任务完成通知，以及任务输出/
终止行为。
