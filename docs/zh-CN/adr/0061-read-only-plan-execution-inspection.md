# ADR 0061 — 计划执行快照的只读查看

**简体中文** · [English](../../en/adr/0061-read-only-plan-execution-inspection.md)

## 状态

已接受

## 背景

ADR 0060 让每条计划执行任务都携带不可变快照，使后续计划替换不会改写历史。紧凑的 `/tasks` 列表刻意
只显示指纹前缀和已完成步骤数。用户仍需要一种显式方式来确认执行使用了哪份计划修订，同时不能展开每个
任务列表项，也不能把历史文本当作新的指令。

任务 ID 不能成为跨会话历史搜索键。读取快照也不能悄悄把它送入供应商请求：历史计划可能包含用户撰写的
文本，它是过去交接的证据，而不是重复执行的权限。

## 决策

- `SessionStore.get_session_task(session_id, task_id)` 是精确且有界的读取。它会校验不透明任务 ID，先要求
  所提供的会话存在，并同时以两个标识符查询。该任务不在该会话时返回 `None`；不存在全局查找、列表扩展
  或修改行为。
- `AgentConversation` 与 `ProfileConversationController` 只把这一窄读取暴露给活动 TUI binding。它不会获取
  轮次锁、启动模型请求、更改当前计划、追加事件、转换任务、请求审批，或调用工作区/平台适配器。
- 本切片唯一的界面是本地 TUI 命令 `/view-task TASK_ID`。对于带快照的计划执行任务，它会完整渲染已保存
  的目的、指纹和步骤，并给出明确的只读参考提示。`/tasks` 仍是紧凑摘要。不存在的任务或没有快照的旧任务
  不会显示历史细节。
- 该命令不会创建执行、重试、调度器、后台任务、审批、工作区、沙箱、ACP 或子代理能力；也不会展示提示词、
  命令、原始工具输出或凭据。

## 后果

用户可以审计已完成、失败或取消的执行实际接收过的计划，不会把它与活动计划混淆。快照只在明确的本地操作
之后显示，并且被限制在当前打开的会话中。

跨会话历史浏览、任务结果与步骤关联、任务图、调度、任务重试/取消控制、ACP 任务 API 和子代理编排仍是
独立的纵向能力。
