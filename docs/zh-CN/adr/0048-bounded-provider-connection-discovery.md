# ADR 0048：有界供应商连接发现

**简体中文** · [English](../../en/adr/0048-bounded-provider-connection-discovery.md)

状态：已接受

## 背景

本地供应商校验可以证明 profile、代理策略和端点形式在结构上有效，却无法区分错误 API
密钥、错误基础地址或错误线路协议。此前第一次真实对话才会充当连接测试，而且用户离开
设置后才会看到失败。远程模型目录可以校验路由并提供当前标识，但它是携带凭据、不可信
且并非所有兼容服务器都实现的网络边界。

## 决策

- 新增 `ProviderCatalog` 端口和 HTTPX 适配器。发现必须由用户显式触发；保存 profile
  继续保持离线，绝不会自动开始发现。
- 复用草稿 profile 解析后的 `HttpClientPolicy`。凭据只放在协议原生请求头中，包括
  Gemini 的 `x-goog-api-key`；绝不放入查询字符串、界面消息、对象表示或持久化目录。
- 对 OpenAI 兼容/Responses、Anthropic 和 Gemini profile 使用只读模型列表请求；不发送
  提示，也不启动模型生成。
- 单次响应限制为一兆字节，渲染目录最多包含 200 个唯一模型标识。结果只存在于当前设置
  页，并保留手动模型输入作为兼容回退。
- 分类认证、端点/协议、超时、限流、服务端、代理、网络、超限和异常响应错误。HTTP 错误
  响应正文绝不读取或显示；传输错误中的已配置凭据和代理值会被脱敏。
- 测试期间不保存 profile。选择发现的模型只更新草稿；只有“保存并使用”会持久化。

## 影响

用户可以在开始对话前诊断常见 401、404 和代理错误，也可以直接选择返回模型而无需复制
标识。发现不会产生模型生成费用，Neuro Code 也不会通过该操作修改供应商状态。目录请求
成功只证明该凭据能够访问对应目录，并不保证账户能使用每个列出的模型，也不保证自定义
兼容服务器实现 `/models`；这类服务器可以保留手动标识并在未通过发现时保存。持久化/
离线目录缓存、超出首个有界响应的供应商专用分页，以及平台钥匙串存储仍属于后续工作。
